# AGENTS.md

Profile repository for `juninmd` (GitHub profile README). The README is partly generated by `scripts/update-readme.mjs`. Living memory for agents lives here and in `GEMINI.md`.

## Stack

- Node.js scripts, `node --test` for tests
- GitHub Actions (`.github/workflows/`), semantic-release config (`.releaserc.json`)
- Package manager: npm (`package-lock.json`)

## Commands

- Install: `npm ci`
- Test: `npm test` (`node --test test/*.test.mjs`)
- Update dynamic README sections: `npm run update:readme` (`scripts/update-readme.mjs`)

## Structure

- `README.md` — profile page; dynamic sections are rewritten by the script
- `scripts/update-readme.mjs` — fetches data and rewrites README sections
- `test/update-readme.test.mjs` — tests for the script
- `assets/hero.svg`, `devcard.svg` — visual elements
- `.github/workflows/` — `validate.yml` (tests and README script), `update-readme.yml`, `release-drafter.yml`, `sast.yml`, `security.yml`
- `ROADMAP.md`, `CHANGELOG.md`, `CONTRIBUTING.md`, `GEMINI.md` — roadmap, history, contribution rules, Gemini guidance

## Conventions

- Keep the logic in each file within about 100 lines; split by responsibility before that.
- Run `npm test` before any PR. New or changed code needs tests.
- Ask before adding a dependency.
- Use the persona prefix in PR titles when an agent works in persona mode: ⚡ Bolt (performance), 🎨 Palette (UX/a11y), 🛡️ Sentinel (security), 💡 Spark (feature).
- Persona mode: one small change per PR, measured or verified first, no breaking change, no sacrifice of readability.
- Persona journaling: read `.jules/<persona>.md` before starting (create if missing) and log only critical learnings as `## YYYY-MM-DD - [Title] | **Learning:** ... | **Action:** ...`.

## Gotchas

- `update-readme.yml` commits README changes to the default branch on its own (`[skip ci]`). Do not edit the generated sections by hand.
- `.releaserc.json` targets `main`/`master` and commits `CHANGELOG.md` with `[skip ci]`.
- Never hardcode tokens or secrets; scan for them before a PR.

## Future Roadmap

3. **Profile consistency:** make all visual elements (badges, SVGs) share one theme and palette.
4. **Test coverage:** add unit tests for any custom script or action added.

## GitHub Actions — padrão obrigatório (@main)

- Referencie as actions internas sempre pelo branch, nunca por SHA:
  - `uses: juninmd/base-actions/<action>@main`
  - `uses: juninmd/base-actions/.github/workflows/<arquivo>.yml@main`
- Não fixe `@<sha>` em `juninmd/base-actions`: a atualização é centralizada no
  `main` e passa a valer no próximo run.
- PRs cujos checks não iniciam por billing/spending limit são mesclados pelo bot central
  `juninmd/base-actions/.github/workflows/auto-merge-billing-blocked.yml`.
  Para impedir o merge automático de um PR, aplique a label `do-not-merge`.
